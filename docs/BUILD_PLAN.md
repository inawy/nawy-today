**القاعدة:** لا ننتقل لمرحلة قبل أن تنجح بوابتها (اختبارات + lint + build). كل مرحلة صغيرة، مستقلة، وقابلة للإلغاء (revert) دون كسر ما قبلها. ما بُني لا يُعاد كتابته إلا بقرار في [DECISIONS.md](./DECISIONS.md).

الترتيب مقصود: **الأجزاء الأخطر والأنقى أولًا** (الوقت، التخزين، التكرار) قبل أي واجهة، لأن أخطاء التقويم الحقيقية تنشأ فيها، وإصلاحها بعد بناء الواجهة مكلف.

## المرحلة 0 — الأساس والبوابات ✅ (أُنجزت 2026-10-13)
**يبني:** Vite + React + TS صارم، Vitest، ESLint flat + Prettier، قواعد فصل الطبقات (D-004)، `brand.json`، GitHub Actions (lint → test → build)، `package-lock.json`.
**بوابة الخروج:** CI أخضر على مشروع فارغ، واختبار دخاني واحد ينجح، وقاعدة lint تفشل فعلًا عند استيراد مخالف (اختبار سلبي).
**نتيجة:** CI أخضر (install ← lint ← format ← 21 اختبارًا ← build). أحد الاختبارات السلبية كشف عيبًا حقيقيًا في قاعدة lint وأُصلح (D-017).

## المرحلة 1 — `core/time` والمنطقة
**يبني:** غلاف التاريخ (D-006): جمع أيام/أشهر، بداية الأسبوع القابلة للضبط، تحويل محلي↔لحظة بالمنطقة، طوال اليوم الحصري، تنسيق عبر `Intl` (ميلادي + هجري ثانوي + أرقام + 12/24).
**اختبارات:** حدود DST (الرياض بلا DST؛ نختبر أيضًا القاهرة/لندن/نيويورك)، نهاية الشهر/السنة الكبيسة، بداية الأسبوع السبت/الأحد/الإثنين، تنسيق AR/EN.
**بوابة:** تغطية كاملة لفروع الدوال العامة، بلا أي استيراد خارج `core`.

## المرحلة 2 — النموذج والتخزين
**يبني:** أنواع `Calendar`/`CalEvent`، مخطط Dexie v1، CRUD بـ tombstones، envelope التصدير والاستيراد مع رفض الإصدارات الأحدث، الترحيل، اللقطات، طلب التخزين الدائم.
**اختبارات:** `fake-indexeddb` لكل عملية؛ جولة تصدير→استيراد؛ استيراد إصدار أحدث يُرفض؛ ترحيل من مخطط وهمي v0 (يحسم قرار `upgrade()` في D-008)؛ tombstone يفوز عند الدمج؛ تعارض `updatedAt`.
**بوابة:** لا مسار حذف فعلي خارج تنظيف tombstones.

## المرحلة 3 — التكرار (يبدأ بـ Spike)
**3a Spike (قصير، يُسجَّل في قرار):** مقارنة `rrule` / `ical.js` / محرك ذاتي على fixtures ذهبية يولّدها سكربت Python بـ `python-dateutil` (أداة تطوير فقط). المعيار: عدد الحالات الناجحة، DST، الحجم، الصيانة.
**3b التنفيذ:** `expand(event, rangeStart, rangeEnd)` يعيد مواقع الأحداث، يدعم `EXDATE` وسجلات override و"هذا وما بعده".
**اختبارات:** FREQ×INTERVAL×BYDAY×COUNT×UNTIL، 31 في الشهر، 29 فبراير، عبر DST، والتعديل المنفرد/المتتالي/الكل، وتحقق property-based (التوسعة داخل المدى دائمًا، ومرتبة، وبلا تكرار).
**بوابة:** نجاح كل الـ fixtures، وأداء توسعة 1000 سلسلة × سنة ضمن الميزانية.

## المرحلة 4 — `core/layout` (خوارزميات نقية)
**يبني:** توزيع الأحداث المتراكبة في أعمدة للـ time grid، وتخطيط شرائط الشهر متعددة الأيام و"+N"، وحساب موضع خط "الآن".
**اختبارات:** حالات تراكب (متتالية، متداخلة، متطابقة، سلاسل)، أحداث عبر منتصف الليل، أحداث بصفر مدة.
**بوابة:** لا أحداث تتراكب بصريًا (خاصية يثبتها property test).

## المرحلة 5 — الهيكل والتصميم والشهر
**يبني:** tokens والثيمات، Shell (شريط علوي/جانبي/درج)، RTL/LTR، عرض الشهر للقراءة فقط من بيانات حقيقية.
**اختبارات:** مكوّنات (Testing Library)، لقطات RTL/LTR، تباين ألوان آلي، e2e: فتح التطبيق وعرض شهر.
**بوابة:** لا شاشة بيضاء مع بيانات تالفة (حدّ أخطاء).

## المرحلة 6 — اليوم والأسبوع
**يبني:** الـ time grid، صف طوال اليوم، خط "الآن"، تمرير/تنقل.
**اختبارات:** مكوّنات + e2e (حدث يظهر في الموضع الصحيح، تراكب).

## المرحلة 7 — إنشاء وتحرير الحدث
**يبني:** البطاقة السريعة، المحرر الكامل، التكرار (واجهة)، حفظ تلقائي، تراجع الحذف 5 ثوانٍ، معالجة فشل الحفظ، "هذا الحدث/ما بعده/الكل".
**اختبارات:** e2e للدورة كاملة (إنشاء→إعادة تحميل→موجود)، تعديل سلسلة بالأوضاع الثلاثة، فشل تخزين محاكى.

## المرحلة 8 — Today والموبايل
**يبني:** شاشة Today، زر "+" العائم، الدرج، لمس 44px، لوحة المفاتيح (`visualViewport`)، زر الرجوع عبر `history`.
**اختبارات:** e2e بحجم هاتف.

## المرحلة 9 — البحث
**يبني:** تطبيع عربي (التشكيل، ألف/همزات، تاء مربوطة/هاء، ياء/ألف مقصورة)، فهرسة بسيطة، نتائج حية.
**بوابة:** ≤ 200ms على 5000 حدث.
